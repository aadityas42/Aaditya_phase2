# 5. IDOR - Santa's little IDOR

## Solution:

- This is about IDOR or insecure direct object reference

- First, we log into a given website using a set of credentials. After this, we use the inspect option, network tab to find out that the session depends on a user id which we can edit under the local storage option to gain access to other users' accounts.

- Next, we click on the eye icon beside the first child. The network tab now has some new requests, one of which has `Mg==` at the end which is just base 64 for 2. We can edit this too by changing it to some other number in base 64.

- There are also some requests which look like a hash, which we can decode using a site like UUID to understand what format was used to generate it since ven though it looks random to us at first, it does follow a format, including the date and time of creation.

- As such, we can use a particular time range, say an hour, to brute force 3600 attacks to gain unauthorised access to things we shouldn't have.
