## 2. Dust_intermediate

## Solution:

- I listed out all of the functions present and disassembled some of them.

-  I tried shinyclean2::main and found that it basically handles the input/output and comparision to print the final result

- I looked at shinyclean2::a after this. What it does is take an input byte, then adds it to a continuous counter and outputs the value from a table at that new index, it does this 21 times.

- Back in main the 21 bytes are collected and stored in an array at `0x613da` location. the expected result here is `ea d9 31 22 d3 e6 97 70 16 a2 a8 1b 61 fc 76 68 7b ab b8 27 96`

- We need to invert this to get the flag. Since only one transform is there on each step and the table is known all we need to do is for each i from 0-20

- find index j where TABLE[j] == expected[i]
   u[i+1] = j
   b[i] = (u[i+1] - u[i]) mod 256

- Doing this gives us our flag.
  
## Flag:

```
DawgCTF{S0000_CL43N!}
```

## 3. Dust_pro

## Solution:

- In the .text/.rodata section, there are 25 consecutive mov instructions which is basically a 25 byte binary

- To get each cahrecter of the flag, we need to XOR one charecter from the 25 byte binary with 1 charecter of a key which is generated when we give an input number

- Since we know that the flag format is DawgCTF{} we know the first 8 charecters of the flag from which we can reverse engineer what the key, and hence our input number should look like.

- XOR of these first 8 charecters with the respective bytes from the 25 byte integer gives us the same key consistently, which is `0x8b, 0x68, 0x69, 0xd4`

- Now that we have the key, we can find the rest of the flag by XOR with the other 16 bytes of the binary we were given.

- Hence, we can obtain our flag in such a manner.
  
## Flag:

```
DawgCTF{4LL_RU57_N0_C4R!}
```
